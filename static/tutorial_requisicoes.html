Como Assinar Requisições HTTP com Token JWT no Flutter

Aprenda a atualizar o código do seu aplicativo Flutter construído na Atividade 1 para incluir o token de autenticação JWT obtido no Login (Atividade 3) e consumir os endpoints protegidos da API sem receber o erro 401 Unauthorized.

Público-Alvo Estudantes de Mobile / Web
Cabeçalho HTTP Authorization: Bearer <token>
Pacote Flutter http: ^1.2.0
Persistência Local shared_preferences
1

O que Mudou na API? (Por que recebo erro 401?)

Nas primeiras atividades, os endpoints de produtos eram abertos para permitir que vocês testassem requisições REST sem preocupação com login.

Agora, a API foi atualizada para o padrão corporativo de microsserviços: todos os endpoints de produtos exigem que a requisição seja assinada digitalmente com um Token JWT válido.

🚨
O que acontece se enviar sem token agora:
A API recusará a conexão imediatamente com status HTTP 401 Unauthorized: 
{
  "detail": "Not authenticated"
}

Quais rotas agora exigem token?

Método Endpoint Status de Acesso Observação
GET /produtos 🔒 Requer Token Listagem de catálogo
GET /produtos/{id} 🔒 Requer Token Detalhes de um produto
POST /produtos 🔒 Requer Token Cadastro de produto
PUT /produtos/{id} 🔒 Requer Token Edição de produto
DELETE /produtos/{id} 🔒 Requer Token Exclusão de produto
POST /notificacoes/enviar 🔒 Requer Token Disparo push geral
GET /auth/me 🔒 Requer Token Dados do usuário logado
POST /auth/login 🔓 Público Gera o token para o app
POST /auth/cadastrar 🔓 Público Cria novas contas
GET /tutorial* e /teste-formulario 🔓 Público Tutoriais HTML didáticos
2

Como o Token JWT Viaja no Cabeçalho HTTP

O padrão da indústria para envio de tokens JWT é o Bearer Token (RFC 6750). O token viaja em um cabeçalho HTTP padrão chamado Authorization:

Estrutura do Cabeçalho HTTP 
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Observe a palavra Bearer (com a primeira letra maiúscula) seguida de um espaço obrigatório e depois a sequência criptográfica do seu token.

💡
O que significa "Bearer"?
Em inglês, Bearer significa "portador". Ou seja: o servidor autoriza qualquer requisição de quem estiver "portando" aquele token assinado pela chave secreta do servidor.
3

Lendo o Token Salvo com SharedPreferences

Na Atividade 3 (Login & Cadastro), quando o usuário fez login com sucesso em /auth/login, vocês salvaram a string access_token no dispositivo com SharedPreferences.

Para usá-lo antes de disparar qualquer requisição para a lista de produtos, basta recuperá-lo:

Recuperando o Token Salvo 
import 'package:shared_preferences/shared_preferences.dart';

Future<String?> obterTokenSalvo() async {
  final prefs = await SharedPreferences.getInstance();
  // Lê a mesma chave onde você salvou no login ('jwt_token' ou 'token')
  return prefs.getString('jwt_token');
}
4

Comparativo Prático: Como Atualizar (Antes vs Depois)

Veja a diferença exata entre como o seu app fazia a requisição na Atividade 1 e como ele deve fazer agora:

❌ Antes (Atividade 1 - Sem Token)

A requisição não informava credenciais. Agora o servidor rejeita com 401 Unauthorized. 

// Sem cabeçalhos de autorização
final response = await http.get(
  Uri.parse('http://10.0.2.2:8000/produtos'),
);
✅ Depois (Com Token Bearer)

Adiciona o parâmetro headers: {'Authorization': 'Bearer $token'}. Acesso liberado! 

// 1. Obtém o token salvo
final token = await obterTokenSalvo();

// 2. Envia no cabeçalho Authorization
final response = await http.get(
  Uri.parse('http://10.0.2.2:8000/produtos'),
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer $token',
  },
);
5

Atualizando Todas as Operações CRUD

Abaixo estão os exemplos práticos em Dart para você copiar e colar diretamente nas funções do seu app Flutter:

1. Listar Produtos (GET /produtos)

_buscarProdutos() com Token 
Future<List<Produto>> buscarProdutosAutenticado() async {
  final prefs = await SharedPreferences.getInstance();
  final token = prefs.getString('jwt_token') ?? '';

  final response = await http.get(
    Uri.parse('$apiBaseUrl/produtos'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $token',
    },
  );

  if (response.statusCode == 200) {
    final List<dynamic> listaJson = jsonDecode(utf8.decode(response.bodyBytes));
    return listaJson.map((item) => Produto.fromJson(item)).toList();
  } else if (response.statusCode == 401) {
    throw Exception('Sessão expirada. Faça login novamente!');
  } else {
    throw Exception('Erro ao carregar produtos: ${response.statusCode}');
  }
}

2. Cadastrar Novo Produto (POST /produtos)

_cadastrarProduto() com Token e Body JSON 
Future<bool> cadastrarProdutoAutenticado(String nome, double preco, String descricao) async {
  final prefs = await SharedPreferences.getInstance();
  final token = prefs.getString('jwt_token') ?? '';

  final payload = jsonEncode({
    'nome': nome,
    'preco': preco,
    'descricao': descricao,
    'disponivel': true,
  });

  final response = await http.post(
    Uri.parse('$apiBaseUrl/produtos'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $token', // <-- TOKEN BEARER AQUI
    },
    body: payload,
  );

  return response.statusCode == 201;
}

3. Atualizar Produto (PUT /produtos/{id})

_atualizarProduto() com Token 
Future<bool> atualizarProdutoAutenticado(int id, double novoPreco, bool disponivel) async {
  final prefs = await SharedPreferences.getInstance();
  final token = prefs.getString('jwt_token') ?? '';

  final response = await http.put(
    Uri.parse('$apiBaseUrl/produtos/$id'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $token',
    },
    body: jsonEncode({
      'preco': novoPreco,
      'disponivel': disponivel,
    }),
  );

  return response.statusCode == 200;
}

4. Remover Produto (DELETE /produtos/{id})

_removerProduto() com Token 
Future<bool> removerProdutoAutenticado(int id) async {
  final prefs = await SharedPreferences.getInstance();
  final token = prefs.getString('jwt_token') ?? '';

  final response = await http.delete(
    Uri.parse('$apiBaseUrl/produtos/$id'),
    headers: {
      'Authorization': 'Bearer $token',
    },
  );

  return response.statusCode == 200;
}

Tratando o Erro 401 e Redirecionando para o Login

Tokens JWT possuem tempo de expiração. Se o aluno ficar muito tempo sem usar o app ou se o token for invalidado, qualquer chamada aos produtos retornará 401 Unauthorized.

A melhor prática de UX é detectar o código 401, limpar o token salvo e mandar o usuário de volta para a tela de login:

Tratamento de 401 e Logout Automático 
void tratarErroAutenticacao(BuildContext context) async {
  // 1. Limpa o token expirado do aparelho
  final prefs = await SharedPreferences.getInstance();
  await prefs.remove('jwt_token');

  if (!context.mounted) return;

  // 2. Exibe aviso amigável ao usuário
  ScaffoldMessenger.of(context).showSnackBar(
    const SnackBar(
      content: Text('Sua sessão expirou. Por favor, entre novamente.'),
      backgroundColor: Colors.orange,
    ),
  );

  // 3. Redireciona para a tela de Login removendo a pilha de telas
  Navigator.pushAndRemoveUntil(
    context,
    MaterialPageRoute(builder: (context) => const LoginPage()),
    (route) => false,
  );
}

Boas Práticas: Criando um Serviço HTTP Centralizado (ApiService)

Para não precisar repetir SharedPreferences.getInstance() e o cabeçalho headers: {'Authorization': ...} em cada função do seu app, crie uma classe de serviço limpa chamada ApiService:

lib/services/api_service.dart 
import 'dart:convert';
import 'package:http/http.dart' as http;
import 'package:shared_preferences/shared_preferences.dart';
import '../models/produto.dart';

class ApiService {
  // Use http://10.0.2.2:8000 para Android ou https://sua-api.onrender.com
  final String baseUrl;

  ApiService({this.baseUrl = 'http://10.0.2.2:8000'});

  /// Gera os cabeçalhos padrão já incluindo o Token Bearer JWT salvo
  Future<Map<String, String>> _getHeaders() async {
    final prefs = await SharedPreferences.getInstance();
    final token = prefs.getString('jwt_token') ?? '';

    return {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $token',
    };
  }

  /// GET /produtos
  Future<List<Produto>> listarProdutos() async {
    final headers = await _getHeaders();
    final response = await http.get(Uri.parse('$baseUrl/produtos'), headers: headers);

    if (response.statusCode == 200) {
      final List<dynamic> dados = jsonDecode(utf8.decode(response.bodyBytes));
      return dados.map((p) => Produto.fromJson(p)).toList();
    }
    throw Exception('Erro ${response.statusCode}: ${response.body}');
  }

  /// POST /produtos
  Future<Produto> criarProduto(String nome, double preco, String descricao) async {
    final headers = await _getHeaders();
    final response = await http.post(
      Uri.parse('$baseUrl/produtos'),
      headers: headers,
      body: jsonEncode({
        'nome': nome,
        'preco': preco,
        'descricao': descricao,
        'disponivel': true,
      }),
    );

    if (response.statusCode == 201) {
      return Produto.fromJson(jsonDecode(utf8.decode(response.bodyBytes)));
    }
    throw Exception('Falha ao cadastrar produto.');
  }

  /// DELETE /produtos/{id}
  Future<void> excluirProduto(int id) async {
    final headers = await _getHeaders();
    final response = await http.delete(
      Uri.parse('$baseUrl/produtos/$id'),
      headers: headers,
    );

    if (response.statusCode != 200) {
      throw Exception('Falha ao excluir produto.');
    }
  }
}

Como Validar suas Requisições no Swagger e cURL

Antes de testar no seu celular ou emulador, você pode validar o funcionamento da autenticação direto pelo navegador ou terminal:

1. Testando no Swagger UI (/docs)

  1. Abra o navegador em http://localhost:8000/docs.
  2. Repare que agora os endpoints /produtos possuem um ícone de cadeado preto à direita.
  3. Clique no botão verde superior Authorize (com cadeado).
  4. Digite o usuário aluno e a senha 123456 e clique em Authorize.
  5. Pronto! Todas as rotas testadas pelo Swagger agora enviarão o token automaticamente.

2. Testando via Terminal com cURL

Obtenha o token pelo endpoint de login:

1. Obter Token via cURL 
curl -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "aluno", "senha": "123456"}'

Em seguida, use o token recebido no cabeçalho Authorization para listar os produtos:

2. Listar Produtos com Bearer Token 
curl -X GET http://localhost:8000/produtos \
  -H "Authorization: Bearer <COLE_SEU_TOKEN_AQUI>"
